# 3.6.0 Top bar — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the wrapping row of ~18 buttons with grouped menus (File, Edit, View, Clients, Help), an always-visible core, a Client › Site › Rack breadcrumb, an avatar menu, keyboard shortcuts shown in menus, and tidier side panels.

**Architecture:** A reusable `MenuBar` (src/Menu.tsx) generalises today's `ExportMenu` dropdown. Shortcuts live in one table (src/shortcuts.ts) used both by the key handler and the menu labels. The breadcrumb resolves the open rack's client and site with a pure helper over `ClientStore` data (src/location.ts). Help › What's new reads `CHANGELOG.md` at build time (`?raw` import).

**Tech Stack:** React 18 + TypeScript, Vite; tests are `npx tsx scripts/*.test.ts` (pure functions only).

**Spec:** `docs/superpowers/specs/2026-11-16-look-and-feel-design.md` (section "Top bar").

## Global Constraints

- One front end for desktop and web. Web-only code stays behind `IS_WEB`; no static `@tauri-apps` imports.
- All colours via `v("token")` from `src/theme.ts`; `scripts/theme.test.ts` "no stray hex" must stay green.
- No new npm dependencies. No behaviour change to editing, saving, routing or the Clients screen beyond what is listed.
- UI copy: plain, short sentences; menu labels in sentence case ("Save as", "Import Auvik…"). An item that opens a dialog ends with "…".
- Shortcuts don't fire while typing in INPUT/TEXTAREA/SELECT, except Ctrl+S / Ctrl+Shift+S (as today).

## Review Focus

1. Menus must not be clipped by the top bar or covered by the canvas: dropdowns are `position: fixed` with a z-index above the rack view and side panels, like `ExportMenu` today.
2. A menu closes on outside click, Escape, window blur, and after running an item; with one menu open, hovering another top-level label switches to it.
3. Disabled items (Undo with an empty stack, Duplicate/Delete with no device selected, Export with no racks) show greyed and do nothing; their hint shows as a tooltip.
4. Breadcrumb for a rack that is in no client: web "Unassigned › <name>", desktop "Unassigned › <file name>"; unsaved new rack: "New rack". Never throws when the client store fails (falls back to the rack name).
5. Narrow windows (1280 px and 1024 px wide): the top bar stays one row; the breadcrumb truncates with an ellipsis instead of wrapping.

**Interfaces (produces):**
- `shortcuts.ts`:
  - `export type Cmd = "new" | "open" | "save" | "saveAs" | "undo" | "redo" | "duplicate" | "delete" | "fit" | "deselect"`
  - `export const SHORTCUTS: Record<Cmd, string>` = `{ new: "Ctrl+N", open: "Ctrl+O", save: "Ctrl+S", saveAs: "Ctrl+Shift+S", undo: "Ctrl+Z", redo: "Ctrl+Y", duplicate: "Ctrl+D", delete: "Delete", fit: "Home", deselect: "Escape" }`
  - `export interface KeyLike { key: string; ctrlKey: boolean; metaKey?: boolean; shiftKey: boolean; altKey?: boolean }`
  - `export function matches(e: KeyLike, shortcut: string): boolean` — case-insensitive key compare; Ctrl matches ctrlKey or metaKey; modifiers must match exactly (Ctrl+Z does not match Ctrl+Shift+Z).
  - `export function commandFor(e: KeyLike): Cmd | null` — also maps Ctrl+Shift+Z → "redo".
- `Menu.tsx`:
  - `export interface MenuItem { label: string; run?: () => void; shortcut?: string; disabled?: boolean; hint?: string; checked?: boolean; items?: MenuItem[] }` plus `export const SEP: MenuItem` (a separator marker, e.g. `{ label: "-" }`).
  - `export function MenuBar({ menus }: { menus: { label: string; items: MenuItem[] }[] })` — top-level labels as flat buttons; dropdown panels `position: fixed`, `z-index: 60`; submenus (`items`) open to the right on hover; `checked` shows a ✓ column; `shortcut` right-aligned in `v("text-dim")`.
  - `export function DropButton({ label, items, title }: { label: ReactNode; items: MenuItem[]; title?: string })` — a single button with a dropdown (used for the avatar menu).

### Task 3: Breadcrumb

**Files:** Create `src/location.ts`, `src/Breadcrumb.tsx`; modify `src/App.tsx` (fill the slot), `src/clients/ClientsPanel.tsx` (props `openClient?: string; focusSite?: number` — select that client and scroll the site's card into view); Test: `scripts/location.test.ts`.

**Interfaces:**
- `location.ts`: `export interface RackLocation { clientKey: string; client: string; siteId: number; site: string }`
  `export function findRackLocation(clients: ClientItem[], match: (r: RackItem) => boolean): RackLocation | null` — first site whose `racks` contains a match.
  `export function sameFile(a: string, b: string): boolean` — desktop path compare: case-insensitive, `\` = `/`.
- `Breadcrumb.tsx`: `export function Breadcrumb({ loc, rackName, dirty, onClient, onSite }: { loc: RackLocation | null | "unassigned"; rackName: string; dirty: boolean; onClient: (key: string) => void; onSite: (key: string, siteId: number) => void })` — renders `Client › Site › Rack •`; client and site are link-style buttons; "Unassigned" is plain text; the rack name is bold; `•` (title "Unsaved changes") when dirty; one line with ellipsis.
- In App: a hook resolves `loc` when the open rack changes (web: `cur?.id`; desktop: `path`) and when the Clients screen closes. Web: `loc` from the `RackMeta` of `GET /api/racks` (it has `client_id`, `client`, `site_id`, `site`; the web client key is `String(client_id)` — confirm against `clients/store.ts` and use whatever key it uses). Desktop: `store.list()` then `store.get(key)` for each, `findRackLocation(..., (r) => !!r.path && !!path && sameFile(r.path, path))`. Unsaved rack → rackName "New rack", loc null. Errors → loc null, no message.
- Clicking client/site opens the Clients screen with `openClient` / `focusSite`.
