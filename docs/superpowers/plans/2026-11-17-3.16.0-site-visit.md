# 3.16.0 Site Visit (was 3.14.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rack panel › Site visit walks a rack top to bottom, one device at a time, so a technician on site can confirm, correct or flag each device, and the rack and devices get today's date in `last_verified`.

**Architecture:** A pure module `src/visit/model.ts` builds the walk list and applies each step to a `Doc`. A lazy dialog `src/visit/SiteVisit.tsx` drives it, applying every step through App's `edit()` so each step is one undo and saves as usual (desktop offline, web normal save). Front end only: no Rust, no server, no API change (`last_verified` already exists on Device and Rack and survives load/save).

**Tech Stack:** React + TypeScript (`rackwright-tauri/src`), tests with `npx tsx scripts/*.test.ts`.

**Spec:** `docs/superpowers/specs/2026-11-17-rackmap-merge-design.md` § Site visit (line 72–74) and § Needs attention (line 70). RackMap's `siteVisit()` is the behaviour reference (copying allowed).

## Global Constraints

- Menu/button copy: rack panel button `Site visit`; dialog title `Site visit · RACKNAME`.
- Rack panel line under usage: `Checked on site YYYY-MM-DD` or `Never checked on site`.
- Step screen: progress `N of M`, counters `A confirmed · B corrected · C not found`, position like `U12–13`, `U12 · left`, `· rear`, and `Last checked YYYY-MM-DD` or `Never checked on site`.
- Help line: `Look at the device in this spot. If the record is right, press Matches. If not, fix the fields, then press Matches.`
- Fields on the step: Name, Status (Active/Spare/Offline/Planned), Manufacturer, Model, Serial, Asset tag, IP.
- Buttons: `Matches` (primary, focused), `Not in the rack` (title `It isn't here: moves it off-rack and sets it to Offline`), `Skip`, `Back` (from step 2 on), `Exit visit`.
- Finish screen: `Visit complete — RACKNAME`, four counts `Confirmed`, `Corrected`, `Not found`, `Skipped`, then either `The rack is marked as checked today. Each confirmed or corrected device has today's date in Last checked on site.` or `Everything was skipped, so the rack is not marked as checked.`; button `Close`.
- Empty rack: `This rack has no devices to check.` with `Close`; the rack is not stamped.
- Walk order: top U first (highest `u + u_size - 1`), then side 0,1,2; devices of type `Blank` and `Cable manager` are left out. Front and rear devices are both walked.
- Dates are local `YYYY-MM-DD` (use the existing today helper the attention code uses, `todayIso` if present).
- Device panel Specs gains a date field `Last checked on site` (`last_verified`).
- Colours only via `v(token)`; literal hex marked `// theme-ok`. UI copy plain language. Test fixtures use made-up names ("Example IT").
- Desktop build must keep working; no `IS_WEB` branches needed.

## Review Focus

1. A device moved or deleted while the dialog is open (another step marked it not in the rack, or undo): the walk skips it instead of crashing or editing the wrong device.
2. Back after Not in the rack: going back shows the previous device; pressing Matches on a device that is now off-rack stamps it but does not put it back (it stays where it is) — test it.
3. Pressing Matches with no field changed is "confirmed"; changing only whitespace is still "confirmed" (values are trimmed); clearing a field deletes it (uses `setField`).
4. Every step is a separate `edit()` so Ctrl+Z undoes one step; Exit midway keeps the steps already done and does not stamp the rack.
5. Name edited to empty: keep the old name (a device needs a name).

### Task 1: Visit model

**Files:**
- Create: `rackwright-tauri/src/visit/model.ts`
- Test: `rackwright-tauri/scripts/visit.test.ts`

**Interfaces:**
- Produces:
  - `export const VISIT_FIELDS: { key: "name" | "status" | "manufacturer" | "model" | "serial" | "asset_tag" | "ip"; label: string }[]` (labels from Global Constraints).
  - `export function visitList(doc: Doc, rackId: number): number[]` — device ids in walk order.
  - `export type VisitAction = "ok" | "missing";`
  - `export function applyStep(doc: Doc, devId: number, action: VisitAction, fields: Partial<Record<VisitField, string>>, today: string): "confirmed" | "corrected" | "missing" | "gone"` — mutates `doc`. `"gone"` when the device no longer exists. `ok`: trims each given field, compares with the current value (`status` compared with `statusOf`), writes changed ones with `setField` (status `active` deletes the key, empty name ignored), sets `last_verified = today`, returns `corrected` if anything changed else `confirmed`. `missing`: `setOffRack(doc, d)`, `status = "offline"`, returns `missing` (no `last_verified`).
  - `export function finishVisit(doc: Doc, rackId: number, counts: { confirmed: number; corrected: number; missing: number }, today: string): boolean` — stamps `rack.last_verified = today` and returns true when any count > 0; else false and no change.
  - `export function posLabel(d: Device): string` — `U12`, `U12–13`, plus ` · left`/` · right` (2 columns), ` · left`/` · middle`/` · right` (3 columns), plus ` · rear` when `face === "rear"`.
