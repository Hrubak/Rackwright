# 3.9.0 Client report (PDF) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A branded quarterly-review PDF for one client, Overview or Detailed, with the user's own summary and recommendations, built in the browser with jsPDF + svg2pdf.

**Architecture:** Report branding (secondary colour, address line, fonts, cover/header/footer artwork) is uploaded by an admin. On the web it lives in the server's settings and assets tables; on the desktop in IndexedDB and localStorage. The last report options per client are stored with the client: on the web in a new `clients.report` column, on the desktop in the `.client.json`. A pure report model is built from the client, its rack docs and the options. A renderer lays the model out page by page and draws the diagrams offscreen in the light palette.

**Tech Stack:** React 18 + TS, jsPDF, svg2pdf.js, Rust axum + rusqlite. One new dev dependency: `@expo-google-fonts/noto-sans` (OFL TTFs) for the default report font.

**Spec:** `docs/superpowers/specs/2026-11-16-look-and-feel-design.md` (Client report (PDF); Settings › Branding; Calls made after the builder review).

## Global Constraints

- No branding in the repository. Tests and examples use "Example IT" and "Example Client".
- Anyone signed in can export a report. Only admins change branding.
- Page: US Letter portrait (612 × 792 pt), margins 54 pt. Every page after the cover has the header artwork (if set), the footer artwork (if set), the address line (if set) and "Page N of M".
- Colours: primary = company accent (default `#2a6fdb`); secondary = `report_secondary` (default `#1f2328`). Drawings use `LIGHT` via `resolveSvgVars(svg, LIGHT)`.
- Font: an uploaded regular and bold TTF/OTF when set, else the bundled Noto Sans regular and bold. Never Helvetica for text, so names with accents always print.
- Report title on the cover: "Network review — <Client>". Copy is plain, short sentences.
- Desktop must build and work with no server. Web-only code stays behind `IS_WEB`, and desktop file access stays behind the existing dynamic `@tauri-apps` imports.
- `web/API.md` changes before the server code. Never end a Rust block with `stmt.query_map(...)?.collect()?` (E0597). Bind the collect to a variable first.

## Rulings (controller)

- Switch port maps in Detailed are drawn with jsPDF shapes: a port grid plus a table of connected ports. SwitchView is HTML, so it can't go through svg2pdf.
- The site-links diagram is pulled out of `clients/Links.tsx` into a pure `LinksDiagram` SVG component, which the screen and the report share.
- Rack drawings reuse the offscreen `faceSvg` from `export/pdf.ts`, moved to `export/svg.ts` and exported. The rack PDF keeps working unchanged.

## Review Focus

- A client with no sites, a site with no racks, or a rack file that fails to load still produces a report. Missing pieces show "No racks in this site." or "Could not load <rack>." instead of failing.
- Long tables (inventory with hundreds of rows) break across pages with the header row repeated, and long cell text is clipped or wrapped, never drawn outside its cell.
- Big racks (52U) and wide diagrams scale down to fit the page, keeping their aspect ratio.
- Branding uploads that fail (wrong type, too large) show the server's message, and the report still builds without them.
- Summary and recommendations with blank lines and long paragraphs wrap and break across pages.

### Task 1: Server — report branding, assets and per-client report options

**Files:** `web/API.md` (first), `web/server/src/settings.rs`, `web/server/src/clients.rs`, `web/server/src/lib.rs`, `web/server/tests/api.rs`.

- Settings keys, validated on `PUT /api/settings`:
  - `report_secondary`: `#rrggbb` or `""`.
  - `address_line`: text, 200 characters at most.
  - `report_font_name`: text, 100 characters at most. This is the display name of the uploaded font.
- Asset names allowed in `PUT/GET/DELETE /api/assets/:name`: `logo`, `font_regular`, `font_bold`, `cover_art`, `header_art`, `footer_art`.
  - Images (`logo`, `*_art`): png, jpeg, svg+xml, webp; at most 2 MB for `logo`, 5 MB for artwork.
  - Fonts: Content-Type `font/ttf`, `font/otf`, `font/sfnt`, `application/x-font-ttf`, `application/x-font-otf` or `application/octet-stream`. The first 4 bytes must be `00 01 00 00`, `OTTO` or `true`. At most 5 MB.
  - Error copy: "Upload a PNG, JPG, SVG or WebP image." / "Upload a TTF or OTF font file." / "That file is too large (5 MB at most)."
  - `GET /api/assets/:name` needs sign-in, not admin, so anyone can build a report. `/api/branding` and `/api/branding/logo` stay as they are.
- Clients get a new column `report TEXT NOT NULL DEFAULT '{}'`. Add it in `clients::migrate` with a PRAGMA table_info check, like `users.prefs`.
  - `GET /api/clients/:id/report` (signed in) returns the stored object.
  - `PUT /api/clients/:id/report` (signed in) takes a JSON object of at most 64 KB and replaces the stored one. 404 for an unknown client.
- Tests:
  - settings: report keys round-trip, and a bad `report_secondary` gets 400;
  - `font_regular` with TTF magic bytes and `application/octet-stream` gets 200, and with PNG bytes gets 400;
  - a 6 MB `cover_art` gets 400;
  - a member (not admin) can GET an asset and gets 403 on PUT;
  - client report: PUT then GET round-trips, an unknown client gets 404, and 70 KB gets 400.
- [ ] Written and self-reviewed line by line (no local Rust; CI compiles).

### Task 3: Report model (pure)

**Files:** `src/report/model.ts` (new), `scripts/report.test.ts` (new).

`buildReportModel(input: { client: ClientItem; docs: Record<string, Doc | string /* error text */>; options: ReportOptions; company: string }): ReportModel`. The docs are keyed by `RackItem.key`.

- `ReportModel = { title; date; preparedFor; preparedBy; level; summary; recommendations; totals: { sites; racks; usedU; totalU; devices; byType: [string, number][] }; sites: SiteSection[]; links: LinkRow[]; inventory: InvRow[] }`.
- `SiteSection = { id; name; address; racks: { key; name; doc?: Doc; error?: string }[]; devices: InvRow[]; switches: SwitchMap[] }`.
- `SwitchMap = { name; ports: { name; used: boolean; to: string; type: string; ip: string }[] }`.
- `LinkRow = { kind; from; to; provider; circuit; bandwidth }`.
- Only the chosen sites. The title is `Network review — ${client.name}`.
- Totals and type counts reuse `docStats`, `inventoryRows` and `typeTotals` from `clients/util.ts`.
- The SwitchMap port "to" text uses the same wording as SwitchView ("hv-01 (NIC1)"). Reuse its helpers, or pull them into a shared function.
- Tests, with a made-up client "Example Client" with two sites, one of them with no racks:
  - totals;
  - site filter;
  - an error rack keeps its error text;
  - an empty site has `racks: []`;
  - link rows name both site names, and the other end shows "Internet" when `site_b` is null.
- [ ] `npx tsx scripts/report.test.ts` passes.

### Task 4: PDF renderer

**Files:**
- `src/report/pdf.ts` (new);
- `src/export/svg.ts` (new: `faceSvg`, `fixColors` and an `svgOf(element, bounds)` helper moved out of `export/pdf.ts`);
- `src/export/pdf.ts` (imports them);
- `src/clients/LinksDiagram.tsx` (new, pure SVG);
- `src/clients/Links.tsx` (uses it);
- `package.json` (dev dependency `@expo-google-fonts/noto-sans`).

`buildReportPdf(model: ReportModel, brand: { primary: string; secondary: string; address: string; company: string; logo?: Blob; cover?: Blob; header?: Blob; footer?: Blob; fontRegular?: ArrayBuffer; fontBold?: ArrayBuffer }): Promise<Uint8Array>`.

- **Fonts:** register the uploaded TTFs, else the bundled `NotoSans_400Regular.ttf` and `NotoSans_700Bold.ttf`, imported with `?url`, fetched and base64'd, then `addFileToVFS` and `addFont`.
- **Images:** SVG artwork is rasterised to PNG at 2× through a canvas. Others go in as they are. Draw each image fitted to width, keeping its aspect ratio.
- **Cover:**
  - the cover artwork across the top, at most 40% of the page height;
  - the company logo, at most 48 pt tall;
  - the title, 26 pt, in primary;
  - "Prepared for <client>", "Prepared by <company>" and the date in secondary.
- **Overview, in order:**
  - Executive summary, skipped when blank;
  - Totals: a small table with sites, racks, U used/total, devices, then devices by type;
  - Site links: the LinksDiagram rendered offscreen, skipped when there are no links;
  - for each site: a heading with the site name and address, then the Infrastructure diagram (InfraView rendered offscreen for each rack doc, skipped when it has no devices), then each rack's front view (`faceSvg`), one rack per page, scaled to fit;
  - Recommendations, skipped when blank.
- **Detailed** adds:
  - per rack, its rear view after the front;
  - per site, switch port maps (a grid of 18 × 14 pt boxes: used ones filled with a primary tint, empty ones light grey, the port name inside; then a table of the used ports) and the site device table;
  - at the end, the full inventory table and the links table.
- **Tables:** a generic `table(cols, rows)` that repeats the header row on each new page and clips cell text with "…" to the column width.
- **Headings:** H1 16 pt bold in primary; H2 12.5 pt bold in secondary.
- **Page furniture:** applied in a final pass over all pages except the cover: the header art, the footer art, the address line at the bottom left and "Page N of M" at the bottom right, in 8.5 pt grey.
- **Diagrams:** a diagram that fails to render becomes the text "This diagram could not be drawn." and the report goes on.
- [ ] Builds, all tests, no stray hex (`src/report/pdf.ts` may use `// theme-ok` for the default colours), tauri-apps grep empty.
