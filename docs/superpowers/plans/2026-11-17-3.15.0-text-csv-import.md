# 3.15.0 Text and CSV Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build or reorganise racks from pasted text or a file in three formats: a rack layout list (top of rack first), RackMap's text format, or CSV (inventory or cable list). Everything goes through a preview with a checkbox on every row. Importing again moves matched devices instead of duplicating them.

**Architecture:** Pure modules in `rackwright-tauri/src/imports/`. Three readers turn text into one `ImportSpec`. `planImport` matches the spec against the open document and produces preview rows. `applyImport` carries out the checked rows on a `Doc`. The preview runs `applyImport` on a clone to show warnings and counts. One dialog, `ImportText.tsx`, replaces today's "Import list…" modal and lets the user fix layout rows before importing (row kind, height, side). Matching against devices already in the document covers the Auvik case: import Auvik first, then import the layout to put those devices at the right U.

**Tech Stack:** React + TypeScript (shared desktop/web front end), tests with `npx tsx scripts/*.test.ts`. No Rust, server or API change: every field used already exists on `Device`/`Rack` and unknown fields survive.

**Spec:** `docs/superpowers/specs/2026-11-17-rackmap-merge-design.md` (sections "Imports" and decision 4 "Reorganise on import"). RackMap source for porting: CheddarBW/RackMap `index.html`, functions `devSpecFrom`, `parseRackText`, `parseDelimited`, `looksDelimited`, `csvToSpec`, `applySpec`, `findPortByName` (copying is allowed).

## Global Constraints

- Version 3.15.0, changelog heading `## 3.15.0 — 2026-11-17`, set with `node scripts/version.mjs 3.15.0`.
- No customer data anywhere in code, tests or fixtures: use "Example IT", "EX-NAS01", "esxi.example.com", 10.0.0.x / 192.0.2.x addresses.
- Colours only through `v(token)`; a literal hex needs `// theme-ok`. UI copy is plain language.
- Desktop and web stay identical; no `IS_WEB` branches are needed in this release.
- U numbering: `Device.u` is the lowest U a device occupies, U1 at the bottom (same as RackMap and `buildFromText`). A layout list's first line is the top of the rack.
- Matching order (first hit wins): serial, MAC (normalised with `normMac` from `src/auvik/parse.ts`), hostname, exact name (case-insensitive), then name-inside-line (an existing device name of 4+ characters appearing as a whole token in a layout line), then group member (below). A row matching two different devices is unchecked with conflict `"Matches more than one device: A, B"`.
- Group member rule: a layout group label `(LABEL)` followed by device lines matches existing devices whose stem equals the label's stem, in order, by trailing `Member <n>`. Stem = lowercase, non-alphanumerics removed, trailing `member\d+`, `(stack|stk)\d*` and digits removed. `(EX-MDF-STACK)` and `EX-MDF-STK01 Member 2` share stem `exmdf`.
- Fields an Auvik import or a user locked (`Device.locked`) are never changed; they show as kept.
- Row actions: `add`, `move` (another U, side, face or rack), `change` (fields only), `same`. Default checked: add, move, change. Unchecked with a reason: conflicts, and "possible match" suggestions.
- Possible match: an unmatched import row whose type is UPS or PDU, with exactly one unmatched device of that type in the target rack or off-rack, and a shared manufacturer word (e.g. "APC") in the name, model or manufacturer → shown matched but unchecked, reason `"Possible match — check before importing"`.
- Devices in the target racks that the import does not mention are listed under "Not in this import (left alone)" and never changed.
- Text copy, exact:
  - Menu: `Import text or CSV…` (replaces `Import list…`).
  - Dialog title: `Import text or CSV`.
  - Format choices: `Automatic`, `Rack layout list (top of rack first)`, `RackMap text format`, `CSV or spreadsheet`.
  - Layout target: `Into rack` with options for each rack in the document plus `New rack`; `Rack height` field for a new rack.
  - Summary line: `N to add · N to move · N to change · N unchanged` (zero parts are kept).
  - Buttons: `Preview`, `Back`, `Cancel`, `Import N changes` (singular `Import 1 change`; disabled `Nothing to import`).
  - Layout row kinds: `Device`, `Empty`, `Note`.
  - Rack too short: `The list needs N U but RACK is M U. Make it N U?` (checkbox, checked by default).
  - Height guess flag: `height guessed`.

## Review Focus

1. **Importing the same file twice:** the second preview shows every row `same` and `Import` is disabled. (Task 4 test `reimport is all same`.)
2. **Target U taken by a device not in the import:** the row is placed in the nearest free slot with the warning `NAME: U12 in RACK is taken — placed at U9 instead.`, or off-rack with `NAME: no free space in RACK — placed off-rack.` (Task 5 tests.)
3. **Layout longer than the rack:** the "Make it N U?" option grows the rack; unchecked, rows that don't fit go off-rack with a warning. (Task 5 test `layout taller than rack`.)
4. **Messy CSV:** BOM, `;` or tab separators, quoted commas and doubled quotes, CRLF, and blank lines all parse. (Task 1 test `csv quirks`.)
5. **Locked fields:** an import never overwrites a locked field, even if its row is checked. (Task 4 test `locked kept`.)

  export type ImpFace = "front" | "rear" | "both";
  export interface ImportDevice {

    name: string;
    type: string | null;          // Rackwright type ("Server", "Switch", "Patch panel", ...)

    u: number | null;             // lowest U, null = unknown

### Task 2: Rack layout list reader

**Files:**
- Create: `rackwright-tauri/src/imports/layout.ts`
- Modify: `rackwright-tauri/src/edit.ts` (add `catalogFind`)
- Test: `rackwright-tauri/scripts/imports.test.ts`

**Interfaces:**
- Consumes: `ImportSpec`, `ImportDevice` (Task 1); `catalogMatch`, `smartTemplate` (`edit.ts`).
- Produces: `parseLayout(text: string): ImportSpec` (kind `"layout"`, every device `rack: undefined`, `u` counted from the top with rack height unknown — see below); `export function catalogFind(name: string): Tpl | null` in `edit.ts` (same lookup as `catalogMatch` but keeps the template's own `u_size`); `export function guessHeight(name: string): { height: number; guessed: boolean }`; `export function placeLayout(spec: ImportSpec, rackU: number): number` (fills each device's `u` from the top of a `rackU` rack, returns the U the list needs).

Line rules (first match wins, after trimming and removing a leading bullet `-`, `*`, `•`, or `1.`):
1. Blank, `#`, `//` → skipped.
2. `[ ... ]` → section marker: contains `back` or `rear` → face `rear`; contains `front` → face `front`; contains `full` (with `width` or `depth`) → face `both`. Applies to following lines until the next marker. Default face `front`.
3. `(LABEL)` on its own → group label for the following device lines until the next empty slot, section marker or group label.
4. Empty space: `^(\d+)\s*U\b.*\b(empty|open|free|spare|blank space|vacant)` or the old `EMPTY` words with optional `(nU)` → an empty slot of n U (default 1).
5. Note: 9 or more words, or ends with `.` and has 6 or more words → `notes.push(line)`, takes no space.
6. Device line, optionally `A | B` (two devices, `cols: 2`, `side` 0 and 1, same U, each sized separately). Height from `(nU)` / `nU` token when present, else `guessHeight`. A trailing parenthetical that is not a height, e.g. `(should be decommissioned)`, moves into `fields.notes` and leaves the name. Type and model come from `smartTemplate(name, height).type` / template model when matched.

`guessHeight`: `catalogFind(name)` → its `u_size`, not guessed. Otherwise defaults, all `guessed: true`: UPS 2, battery pack 2, server/hypervisor 2, storage/NAS 2, everything else 1. The old `(nU)` "Import list" syntax must still parse identically (port `scripts/edit.test.ts` expectations for `buildFromText` into a layout test).

### Task 4: Match and preview rows

**Files:**
- Create: `rackwright-tauri/src/imports/plan.ts`
- Test: `rackwright-tauri/scripts/imports.test.ts`

**Interfaces:**
- Consumes: Task 1–3 types; `Doc`, `Device` (`types.ts`); `normMac`.
- Produces:
  ```ts
  export interface ImportOpts { rackId: number | null; newRackName: string; newRackU: number; growRack: boolean }
  export type Action = "add" | "move" | "change" | "same";
  export interface FieldDiff { field: string; from: string; to: string; kept: boolean }
  export interface Row { id: string; dev: ImportDevice; match: Device | null; action: Action; diffs: FieldDiff[]; on: boolean; reason?: string }
  export interface ImportPlan { rows: Row[]; notInImport: Device[]; links: ImportLink[]; needU: number; rackU: number }
  export function planImport(doc: Doc, spec: ImportSpec, opts: ImportOpts): ImportPlan;
  ```

For a layout spec, `planImport` calls `placeLayout` with the target rack height (or `newRackU`) so rows have U values, and sets `needU`. `move` compares rack, `u`, `side`, `face` with the matched device; `change` compares the fields in `ImportDevice.fields` (string compare, empty import values never count). Locked fields get `kept: true` and don't make a row `change`.

  - `match group members`: the two stack rows match Member 1 and Member 2 in order.
  - `possible ups match`: UPS row matched, `on: false`, reason `Possible match — check before importing`.
  - `conflict`: a row whose name hits two devices → `on: false`, reason starts `Matches more than one device`.
  - `not in import`: `EX-OLD` is in `notInImport`.
  - `reimport is all same`: apply then plan again → every row `same`.
  - `locked kept`: device with `locked: ["ip"]` and import ip differing → diff `kept: true`, action `same`.

### Task 5: Apply

**Files:**
- Create: `rackwright-tauri/src/imports/apply.ts`
- Test: `rackwright-tauri/scripts/imports.test.ts`

**Interfaces:**
- Consumes: Task 4 `ImportPlan`, `Row`, `ImportOpts`; `fromTpl`, `smartTemplate`, `catalogFind`, `addRack`, `resizeRack`, `checkPlace`, `findFree`, `newCable`, `placeNew` (`edit.ts`).
- Produces: `export interface ApplyLog { racksAdded: number; added: number; moved: number; changed: number; cables: number; ports: number; warnings: string[] }`, `export function applyImport(doc: Doc, plan: ImportPlan, opts: ImportOpts): ApplyLog` (mutates `doc`; only rows with `on`).

Order: create missing racks (by name; RackMap/CSV) or the new layout rack; grow the target rack when `growRack` and `needU > rackU` via `resizeRack`; lift every checked moved device off its slot; place rows with a U from the top down (`checkPlace`), falling back to `findFree` with warning `NAME: U12 in RACK is taken — placed at U9 instead.` or off-rack (`placeNew` rules) with `NAME: no free space in RACK — placed off-rack.`; then rows without a U (`placeNew` into the target rack). New devices: `fromTpl(doc, smartTemplate(...))` sized by the row's height, name, face (`plate` → `both` as `buildFromText` does), `cols`/`side`, and fields, specs and services. Layout notes are appended to the target rack's `notes` (one line each, not duplicated on re-import). Links: find ports by name (port `findPortByName`), create a missing port named as written (type guessed: power words → `Power`, `sfp` → `SFP+`, else `RJ45`), skip when either port is already cabled with warning `A port ↔ B port: already connected — skipped.`
