# 3.10.0 Version Check Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tell people when a newer Rackwright exists: desktop users get a download prompt, web admins get an Update now prompt, and everyone on the web gets a Reload prompt after the server is updated.

**Architecture:** Pure version logic in `src/version/check.ts` (tested with `npx tsx`). A new public server endpoint `GET /api/version`. One banner component `src/version/UpdateBanner.tsx` under the top bar, fed by a web hook (server version polling, admin update check) or a desktop hook (GitHub releases). The desktop opens links with `tauri-plugin-opener`, loaded only in desktop builds.

**Tech Stack:** React + TS (`rackwright-tauri/src`), Rust axum (`web/server`), Tauri 2 (`src-tauri`).

**Spec:** `docs/roadmap.md`, "Version check" bullet under Look and feel (user decisions 2026-11-17: desktop prompt + download link to the public GitHub release; web admin banner with Update now plus a Reload prompt for everyone).

## Global Constraints

- Public repository for releases: `Hrubak/Rackwright`; desktop release tags are `desktop-v<version>` (made by `.github/workflows/desktop-exe.yml`).
- Desktop checks on start (after 5 s) and once a day while running; last check time in localStorage `rw.verCheckAt`, skipped version in `rw.verSkip`. No check more often than every 24 h unless the person uses Help › Check for updates.
- Web, everyone: compare `GET /api/version` with the page's own version every 10 minutes and when the tab regains focus.
- Web, admins: run the existing update check (`POST /api/admin/update/check`) on load at most once a day (`rw.updCheckAt`); never start an update without the person clicking.
- The web bundle must not contain `@tauri-apps` code (`grep -l tauri-apps ../web/dist/assets/*.js` prints nothing): import the opener plugin dynamically behind `!IS_WEB`, as `backend.ts` does.
- A failed check (offline, GitHub rate limit, git unreachable) is silent: no banner, no error toast. Help › Check for updates reports the failure in plain words.
- Colours through `v(token)` only. Plain-language copy.

## Review Focus

1. Versions that sort wrongly as strings ("3.10.0" vs "3.9.0"): compare numerically (Task 1 test).
2. GitHub returns drafts, prereleases, or non-desktop tags: ignored (Task 1 test).
3. The page is newer than the server (admin opened the page from a fresh build before the server restarted, or a cached page): no Reload prompt; only prompt when the server is newer (Task 1 test on `serverNewer`).
4. An admin's check says `update_available` but `latest_version` equals the current version (docs-only commit): no banner (Task 1 test).
5. Unsaved changes when Reload is clicked: the existing leave warning shows (Task 3 browser check).

### Task 1: Version logic

**Files:** Create `src/version/check.ts`; Test `scripts/version.test.ts`.

**Interfaces — Produces:**
- `cmpVer(a: string, b: string): number` (numeric per part, missing parts = 0, leading "v" ignored).
- `newestDesktop(releases: { tag_name: string; draft: boolean; prerelease: boolean; html_url: string; published_at: string }[], current: string, skip: string | null): { version: string; url: string } | null`: newest `desktop-v*` release newer than `current`, not draft/prerelease, and not equal to `skip` (a skipped version still lets a newer one through).
- `serverNewer(server: string, page: string): boolean` = `cmpVer(server, page) > 0`.
- `adminOffer(check: { version: string; latest_version: string; update_available: boolean }): string | null`: the newer version to offer, or null.
- `due(lastIso: string | null, now: Date, hours = 24): boolean`.

- [ ] Step 1: failing tests: `cmpVer("3.10.0","3.9.0") > 0`, `cmpVer("v3.9","3.9.0") === 0`; `newestDesktop` over `desktop-v3.9.0`, `desktop-v3.11.0` (prerelease), `desktop-v3.10.0`, `web-v9.0.0` with current `3.9.0` gives `3.10.0`; with skip `3.10.0` gives null; `serverNewer("3.9.0","3.10.0") === false`; `adminOffer({version:"3.10.0", latest_version:"3.10.0", update_available:true}) === null`; `due(null, now) === true`, `due(now-23h) === false`.

### Task 4: Desktop prompt

**Files:** Modify `src-tauri/Cargo.toml` (`tauri-plugin-opener = "2"`), `src-tauri/src/lib.rs` (`.plugin(tauri_plugin_opener::init())`), `src-tauri/capabilities/default.json` (add `"opener:default"`), `package.json` (`@tauri-apps/plugin-opener` ^2), `src/version/useDesktopUpdates.ts`, `src/App.tsx` (Help menu item "Check for updates…" on the desktop), `src/HelpDialogs.tsx` if the result needs a small dialog.

Behaviour: fetch `https://api.github.com/repos/Hrubak/Rackwright/releases?per_page=30` (header `Accept: application/vnd.github+json`); `newestDesktop(...)`; banner "Rackwright {v} is available." [Download] [Skip this version] [×]. Download opens the release `html_url` with `openUrl` from the opener plugin. Skip stores `rw.verSkip`. × hides until the next daily check. Help › Check for updates ignores the 24 h limit and the skip, and shows "You have the newest version ({v})." or the failure text "Could not check for updates. Check your internet connection."
