**Rulings made in this plan (check these):**
1. **Catalog wattage.** Only UPS models get `rated_w` in `catalog.json` (from the model number, list in Task 1). No typical `power_w` is invented for servers or switches: a device's draw is unknown until someone types it in Specs (design call 6, "unknown is unknown"). PDUs get a `rated_w` field in the device panel but no catalog value.
2. **Dual power supplies.** A device fed through two inlets counts its watts split evenly across the connected inlets for each upstream PDU/UPS; the rack and room count it once.
3. **Battery packs** (catalog type UPS, model or name matching `/battery pack|EBM|battery module/i`) are not UPSes for load or battery alerts.
4. **Runtime** is not estimated (no battery capacity data). If the UPS has `specs.runtime` it is shown as typed.
5. **Who is skipped.** Devices with status `planned` raise no alerts and are not in the IP index. Everything else counts.
6. **"Not checked on site"** alerts are `info`. Every rack will raise one until 3.14.0 adds Site visit, so lists group them per client into one line ("3 racks not checked on site in 90 days").

## Global Constraints

- Alert levels and rules (exact): warranty ended → `critical` "Warranty ended YYYY-MM-DD"; warranty ends in 0–60 days → `warning` "Warranty ends in N days". UPS battery due = `battery_date` + 3 years: overdue → `critical` "UPS battery replacement overdue (due YYYY-MM-DD)"; due in 0–60 days → `warning` "UPS battery due in N days". UPS or PDU load over 80 % of rated → `warning`, over 100 % → `critical`, "Load 900 W is 90% of 1,000 W" (prefix "At least " when any downstream device is unknown). Rack with at least one device and `last_verified` missing → `info` "Never checked on site"; older than 90 days → `info` "Not checked on site since YYYY-MM-DD". Same IP on two devices of one client → `warning` "IP 10.0.0.5 is also used by NAS-01, Printer" (one alert per device per IP).
- Dates are `YYYY-MM-DD` strings; day differences are computed in UTC. Every pure function takes `today: string`; screens pass the local date (`new Date().toLocaleDateString("en-CA")`).
- IPs read from `device.ip` (may hold several, split on comma, semicolon or whitespace) and `device.oobm.ip`. Valid IPv4 only; ignore `0.0.0.0`, `127.*`, addresses ending `.255`, and octets > 255. Endpoints are not indexed.
- Power: a device's watts = `device.power_w` if set, else `catalogFor(device)?.power_w`, else unknown (`null`). Rated = `device.rated_w` ?? `catalogFor(device)?.rated_w`. UPS = `type === "UPS"` and not a battery pack; PDU = `type === "PDU"`. Power paths follow Rackwright's power cables inside one document (outlet `Out…` → inlet, `isOutlet` in `edit.ts`); nothing crosses documents (design call 2).
- Rack circuit: `Rack.circuit?: string` (exists) and new `Rack.volts?: 120 | 208` (missing = 120). Amps = watts / volts, one decimal. BTU/hr = watts × 3.412, rounded.
- Totals with unknowns read "at least 555 W, 3 devices unknown"; with none, "555 W". Watts formatted with `toLocaleString("en-US")`.
- Same behaviour on web and desktop. Colours via `v(token)` only (`danger`, `danger-bg`, `warn`, `ok`, `text-muted`…); a literal hex needs `// theme-ok`. Plain-language copy. Tests and mocks use made-up names ("Example IT", "Example Client", 10.0.0.x addresses).
- Do not touch `web/`, `src-tauri/`, `.superpowers/` or `public/`.

## Review Focus

1. A rack where nothing has wattage (every existing rack): headers and panels say "Power unknown — set Power (W) in Specs", never "0 W", and no load alert fires. (Task 1 test `budget all unknown`.)
2. A power loop or a PDU daisy-chained into another PDU and back: roll-up terminates and counts each device once per feed. (Task 1 test `loop`.)
3. The same device listed with its IP in `ip` and `oobm.ip`, or the same IP twice in one `ip` field: not a clash with itself. (Task 2 test `self not clash`.)
4. A client rack document that failed to load (string in `docs`): attention lists skip it and still show the rest; the card shows "Could not read" as today. (Task 2 test.)
5. A rack opened outside any client (desktop file, web unassigned rack): "IP!" tags still mark clashes inside that document, and nothing crashes while the client's other racks load. (Task 3 browser check.)

- `devWatts(d: Device): number | null`; `ratedW(d: Device): number | null`; `isUps(d: Device): boolean`; `isPdu(d: Device): boolean`.
- `interface Feed { devId: number; kind: "ups" | "pdu"; loadW: number; unknown: number; ratedW: number | null; pct: number | null }` (pct rounded; null without rated).
- `interface RackPower { rackId: number; w: number; unknown: number; circuit: string; volts: 120 | 208; amps: number }`; `interface CircuitPower { name: string; volts: 120 | 208; w: number; unknown: number; amps: number; racks: string[] }`.

- `feedFor(budget, devId): Feed | undefined`; `fmtW(w: number, unknown: number): string` ("at least 1,200 W, 2 devices unknown" / "1,200 W" / "Power unknown" when w = 0 and unknown > 0); `btu(w: number): number`.
