# 3.12.0 Rooms and Floor Plans Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sites hold rooms; each room has a floor plan with its racks and objects (doors, cooling, power panels, desks, labels) that you can move, rotate and resize, with lines for cabling between racks.

**Architecture:** A site's rooms are one JSON value stored with the site: a `rooms` TEXT column on `sites` (web) and `sites[].rooms` in `.client.json` (desktop). Pure room logic (`src/rooms/model.ts`: migration, footprints, free-tile search, RackMap's `resizeRoom`) is tested under Node. A `FloorPlan` SVG component edits one room; the client page gets a Floor plan tab.

**Tech Stack:** React + TS (`rackwright-tauri/src`), Rust axum + rusqlite (`web/server`). No local Rust: CI is the first compile.

**Spec:** `docs/superpowers/specs/2026-11-17-rackmap-merge-design.md` (Data › Rooms; Floor plan; calls 1 and 3). RackMap source: `CheddarBW/RackMap` `index.html` — `fp` (line ~833), `tileFree`/`findFreeTile` (~838-850), `floorRoomHTML`/`drawFloorLinks` (~1374-1440), `resizeRoom`/`applyRoomResize` (~2335-2392), `OBJ_TYPES` (~619). **Ruling (deviation from the design's Data section):** rooms are stored as a JSON value on the site (`PATCH /api/sites/:id {rooms}`) instead of a separate rooms table with its own endpoints. Same behaviour, one round trip per save, mirrors how desktop stores them; cheap to split into a table later if rooms need their own permissions.

## Global Constraints

- Room shape (exact field names): `Room { id: number; name: string; w: number; d: number; allow_overlap?: boolean; objects: RoomObject[]; racks: RackSpot[] }`, `RoomObject { id: number; type: "door" | "ac" | "panel" | "desk" | "label"; x: number; y: number; w: number; h: number; label: string }`, `RackSpot { key: string; rack: number; x: number; y: number; rot: 0 | 90 | 180 | 270 }`. `key` = the site's RackItem key (web `r<id>`, desktop the stored path); `rack` = the rack's id inside that document. Units are tiles; one tile = 2 ft, or 600 mm when Settings › Units is metric. Default room 14 × 9 tiles.
- A rack document belongs to exactly one room of its site. A rack document listed in the site but in no room shows in the first room; a site with no rooms is shown as one room "Main room" with all its racks placed left to right on row 1 (`ensureRooms`). Nothing is written until the person edits the plan.
- Object type labels: Door, Cooling / CRAC, Power panel, Desk / bench, Label / zone.
- Rack footprint: 1 × 2 tiles at rot 0/180, 2 × 1 at 90/270 (RackMap `fp`). The rack's front edge is highlighted (rot 0 = bottom edge).
- Server: `rooms` column `TEXT NOT NULL DEFAULT '[]'`; PATCH accepts `rooms` only if it is a JSON array and at most 256 KB; GET client returns each site's `rooms` parsed. Never end a Rust block with `stmt.query_map(...)?.collect()?` (E0597): collect into a `let` first.
- Desktop and web both keep working; `.client.json` unknown fields survive; older apps ignore `rooms`.
- Colours via `v(token)` only; plain-language copy; tests and mocks use made-up names.

## Review Focus

1. A site with racks but no rooms (every existing site): Floor plan shows "Main room" with all racks placed, without writing anything until an edit. (Task 1 test `ensureRooms`.)
2. Shrinking a room so things don't fit with overlap off: nothing changes and the person is asked to keep the size or allow overlapping (RackMap `applyRoomResize`). (Task 1 test.)
3. A rack document removed from the site, or deleted, while the room still lists it: its spots are dropped on load, no crash. (Task 1 test `cleanRooms`.)
4. Two people saving the same site's rooms on the web: last save wins, and the plan reloads after a save so it shows what was stored. (Task 4 browser check.)
5. A rack document holding several racks (e.g. Main Rack and Lab Rack): each physical rack gets its own spot. (Task 1 test.)

### Task 1: Room model

**Files:** Create `src/rooms/types.ts`, `src/rooms/model.ts`; Test `scripts/rooms.test.ts`.

**Interfaces — Produces:**
- Types from Global Constraints, plus `OBJ_TYPES: Record<RoomObject["type"], string>`.
- `footprint(rot: number): { w: number; h: number }`.
- `ensureRooms(rooms: Room[] | undefined, racks: { key: string; rackIds: number[] }[]): { rooms: Room[]; changed: boolean }` — adds "Main room" when empty; places unplaced racks with `findFreeTile` in the first room; drops spots whose key/rack no longer exist (`cleanRooms` behaviour folded in, also exported as `cleanRooms(rooms, racks)`).
- `occupied(room: Room, except?: { kind: "rack" | "obj"; id: string | number }): Set<string>`; `tileFree(room, x, y, w, h, except?): boolean` (in bounds and, unless `allow_overlap`, not overlapping); `findFreeTile(room, w, h): { x: number; y: number } | null` (top-left first, row by row).
- `resizeRoom(room: Room, w: number, d: number, scale: boolean): { room: Room; failed: number }` — port of RackMap `resizeRoom` (wall items stay on walls, rack rows stay together, nearest free spot), returning a new room.
- `nextId(room: Room): number`.

### Task 3: Floor plan editor

**Files:** Create `src/rooms/FloorPlan.tsx`, `src/rooms/floorLinks.ts`; Test `scripts/rooms.test.ts` (add cases).

**Interfaces — Consumes:** Task 1. **Produces:** `<FloorPlan room docs units onChange onOpenRack onSelect selected />` where `docs: Record<string, Doc | string>`, `onChange(room: Room)` (the parent saves), `onOpenRack(key: string, rackId: number)`. `floorLinks(room, docs): { a: string; b: string; data: number; power: number }[]` — counts cables between different racks of the same document (spot ids `key#rack`); cables between documents are not counted (spec call 1).

Drawing (RackMap `floorRoomHTML`): SVG grid of tiles with the room outline, a scale note "1 tile = 2 ft" (or 600 mm). Racks: box of `footprint(rot)` with name and `usedU/totalU`, the front edge as a thick accent line. Objects: dashed boxes with label, door hatched. Data links as arcs between rack centres with a count badge; power links dashed in the warn colour; toggle "Show cabling between racks". Interaction: pointer-drag moves a rack or object by whole tiles (only to free tiles unless overlap is allowed; snaps back otherwise); R while dragging rotates by 90°; click selects; double-click a rack calls `onOpenRack`; objects resize by dragging a corner handle (min 1 × 1). Delete key removes a selected object (racks can't be deleted here). Identical boxes with overlap on draw as side-by-side slices with a "1/2" badge.
