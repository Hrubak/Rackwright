# 3.5.0 Groundwork and identity — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every UI and drawing colour comes from theme variables (dark looks exactly as today), and Rackwright gets a real logo and app icon (exe, favicon, sign-in page, top-bar corner, About).

**Architecture:** `src/theme.ts` owns the token names and the dark palette, writes them as CSS custom properties `--rw-<token>` on `<html data-theme="dark">`, and offers `v("token")` → `"var(--rw-token)"` for inline styles and SVG attributes. Exports resolve `var(--rw-…)` back to literal colours before svg2pdf. A scan test forbids new hex literals outside an allowlist.

**Tech Stack:** React 18 + TypeScript, Vite, Tauri 2 (`npx tauri icon`), jsPDF + svg2pdf.js, tests run with `npx tsx scripts/*.test.ts`.

**Spec:** `docs/superpowers/specs/2026-11-16-look-and-feel-design.md`

## Global Constraints

- Dark must look the same as 3.4.0. Every replaced hex maps to a token whose dark value is that same hex.
- One front end for desktop and web; shared-file edits small; no `@tauri-apps` imports outside dynamic imports.
- No new npm dependencies.
- No company/customer names anywhere (run the customer-data scan from HANDOFF.md before commit).
- UI copy: plain, short sentences.
- Faceplate artwork (`src/Plate.tsx`), `src/catalog.json`, user-chosen device/cable colours and port-type colours (`PORT_COLORS`) are data, not theme: they keep literal colours.

## Review Focus

1. PDF export after the change: SVG attributes now hold `var(--rw-…)`, which svg2pdf cannot read; a rack PDF must come out with the same colours as 3.4.0 (Task 3 test + browser check).
2. `#rgba`/`#rrggbbaa` and `rgba()` colours in inline styles (e.g. `#000a`, `#000d`) must keep their transparency when tokenised (Task 1 test: token values may be 4/8-digit hex).
3. `button:hover` / `input:focus` rules in `index.html` use `!important` colours; they must use variables too, or hover looks wrong in later themes (Task 2 scan covers `index.html`).
4. The sign-in page renders before `App` mounts: theme variables must already be applied there (Task 1: `applyTheme` runs in `main.tsx` before render).
5. Desktop exe icon: `icon.ico` must contain 16–256 px sizes generated from the new mark, and the Windows taskbar shows it (Task 4 check after the Desktop exe build).

### Task 1: Theme module

**Files:**
- Create: `rackwright-tauri/src/theme.ts`
- Modify: `rackwright-tauri/src/main.tsx` (call `applyTheme("dark")` before `createRoot(...).render`)
- Test: `rackwright-tauri/scripts/theme.test.ts`

**Interfaces:**
- Produces:
  - `export type ThemeName = "dark"` (Task 3.8.0 adds `"light"`)
  - `export const DARK: Record<Token, string>`; `export type Token = keyof typeof DARK`-style union of token names (kebab-case, e.g. `"bg"`, `"panel"`, `"text"`, `"rack-post"`)
  - `export const v = (t: Token) => \`var(--rw-${t})\``
  - `export function applyTheme(name: ThemeName, el?: HTMLElement): void` — sets `data-theme` and every `--rw-*` property on `el ?? document.documentElement`
  - `export function resolveVars(s: string, palette: Record<string, string>): string` — replaces every `var(--rw-x)` (optionally with a fallback `var(--rw-x, #fff)`) by `palette[x]`; unknown tokens use the fallback or are left as is

Token set: start from the chrome roles (`bg #14161a`, `panel #1b1d21`, `panel-2`, `control #2a2d33`, `border #3a3d42`, `border-subtle #2c2f35`, `text #e6e8eb`, `text-muted #9aa0a6`, `text-dim #8b9097`, `text-faint #6b717a`, `accent #2a6fdb`, `accent-soft #2a3a52`, `select #ffd33d`, `danger #f85149`, `ok #2ea043`, `ok-bright #3ddc5b`, `warn #d29922`, `focus #4aa3ff`, `scrollbar #33363c`, `hover #363a42`, `hover-border #5a5f67`, `overlay #000a`) and add one token per distinct drawing role found in Task 2 (rack frame shades, U stripes, U labels, rack title/subtitle, off-rack area, diagram node/edge/label colours). Implementers may add tokens; every value must equal the hex it replaces.

### Task 2: Move colours to tokens

**Files (modify):** `index.html` `<style>` block; `src/web.tsx` (`btn`, `inp`), `WebShell.tsx`, `App.tsx`, `RackPicker.tsx`, `ModelPicker.tsx`, `PortsEditor.tsx`, `RackFrame.tsx`, `RackView.tsx`, `Cables.tsx`, `VmLinks.tsx`, `edit.ts` and `cableView.ts` where they hold UI colours, `src/clients/*.tsx`, `src/auvik/*.tsx`, `src/views/*.tsx` and `views/*.ts`, `src/export/ExportMenu.tsx`. Add tokens to `theme.ts` as needed.

**Interfaces:** Consumes `v`, `DARK` from Task 1.

Rules:
- Inline style / SVG attribute colour → `v("token")`. In `index.html` CSS → `var(--rw-token)`.
- Data colours stay literal with `// theme-ok`: device default fill (`#3b6ea8`), default cable colour (`#1f6feb`), `PORT_COLORS`, link-type colours in `clients/util.ts`, view-kind colours in `views/kinds.ts` if they encode meaning in legends, the iDRAC/UAP faceplate bits in `RackView.tsx` lines ~24–32.
- Functions that compute on a colour string (`shade(col, -70)`, `fgFor(...)`, `textOn`) must receive a literal hex: pass `DARK[token]` there, never `v(...)`, and mark the line `// theme-ok` only if it still contains a hex.
