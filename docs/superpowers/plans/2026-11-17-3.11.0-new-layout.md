# 3.11.0 New Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Rackwright RackMap's client-first layout: a Clients dashboard home, client pages with tabs, an equipment sidebar, and a tabbed device panel with the new device fields.

**Architecture:** App.tsx gains a `screen` state (home, client page, rack editor). The Clients modal (`clients/ClientsPanel.tsx`) becomes a full page (`clients/ClientPage.tsx`) whose Racks tab shows the existing rack editor. The right-hand properties panel's device part moves into `panel/DevicePanel.tsx`; the left catalog list moves into `equip/EquipmentSidebar.tsx`. Pure logic lives in `.ts` files with `npx tsx` tests.

**Tech Stack:** React 18 + TypeScript + Vite (`rackwright-tauri/src`), shared by the Tauri desktop app and the web build (`IS_WEB`). No server change: new device fields ride in `.rack.json` (the Rust model keeps unknown fields in `extra`).

**Spec:** `docs/superpowers/specs/2026-11-17-rackmap-merge-design.md` (Layout section and calls 1, 2, 7). RackMap source for look and behaviour: `CheddarBW/RackMap` `index.html` (`dashboardHTML`, `deviceDrawer`, `renderPalette`); copying its code is allowed.

## Global Constraints

- Desktop and web both keep working; `npm run build` and `npm run build:web` pass; `grep -l tauri-apps ../web/dist/assets/*.js` prints nothing.
- Colours only through `v(token)` from `src/theme.ts`; a literal hex needs `// theme-ok` (the theme test enforces this). Light and dark must both read well.
- `.rack.json` stays one format: new fields are optional, unknown fields survive, and clearing a field deletes its key (no empty strings written).
- UI copy is plain language: short sentences that say what to do.
- Tests and mocks use made-up names only ("Example IT", "Example Client", "Head Office", "Branch"). Never real customer names, IPs or hostnames.
- Keep Rackwright's menus (File, Edit, View, Clients, Help), cable drawing, faceplates, the four views (Rack, Infrastructure, Switch, Endpoints), Undo/Redo/Save, themes and the leave-with-unsaved-changes warning.
- Floor plan tab is NOT in this release (3.12.0).

## Review Focus

1. A client with no sites, or a site with no racks: dashboard card, client page and every tab show an empty state with what to do next, no crash. (Task 5 and 6 tests.)
2. A rack document that fails to load (`docs[key]` is an error string): cards, Inventory and Cabling skip it and say which rack could not be read. (Task 5 and 6 tests.)
3. Leaving the rack editor with unsaved changes (Home, another client, another rack): the existing unsaved-changes prompt appears before anything is lost. (Task 7 browser check.)
4. An old `.rack.json` with none of the new fields: the device panel shows blanks, and opening and closing it without typing leaves the file byte-identical. (Task 1 test.)
5. Windows narrower than 1280 px: the sidebar collapses to a strip and the device panel overlays the rack instead of squeezing it to nothing. (Task 3 and 4 browser checks.)

### Task 1: Device fields and device helpers

**Files:**
- Modify: `src/types.ts` (Device, Rack)
- Create: `src/device/info.ts`
- Test: `scripts/device.test.ts`

**Interfaces:**
- Produces:
  - Device optional fields: `status?: DevStatus; manufacturer?: string; hostname?: string; asset_tag?: string; os?: string; role?: string; owner?: string; purchase_date?: string; warranty_exp?: string; power_w?: number; battery_date?: string; rated_w?: number; last_verified?: string; services?: Service[]; specs?: Record<string, string>`. Rack optional: `last_verified?: string; circuit?: string`.
  - `type DevStatus = "active" | "spare" | "offline" | "planned"`; `interface Service { name: string; port: string; proto: string; status: string; notes: string }`.
  - `STATUSES: { v: DevStatus; label: string }[]` (Active, Spare, Offline, Planned), `statusOf(d: Device): DevStatus` (missing = "active").
  - `SPEC_FIELDS: { key: keyof Device; label: string; kind: "text" | "date" | "number" }[]`, in this order: Manufacturer, Model, Serial, Asset tag, Hostname, IP, MAC, OS, Role, Owner, Purchase date, Warranty ends, Power (W), and for type UPS also Battery installed, Rated (W).
  - `setField(d: Device, key: keyof Device, value: string | number | undefined): void`: empty string / undefined / NaN deletes the key.
  - `connectedTo(doc: Doc, devId: number): { dev: Device; links: number }[]`: other devices joined by a cable to any of this device's ports, with cable counts, sorted by name; excludes power cables (`isPowerCable` from `views/infra.ts`).
  - `powerPath(doc: Doc, devId: number): { port: string; chain: { dev: string; port: string }[] }[]`: for each `type === "Power"` port that is not an outlet (`isOutlet` from `edit.ts`), follow its cable to the other device's outlet, then from that device's inlet onward, up to 6 hops, stopping at a loop.
  - `copyAsText(doc: Doc, devId: number): string`: name, type, model, rack and U, IP, serial, then one line per connected device, as RackMap's "Copy as text".

- [ ] **Step 2:** `npx tsx scripts/device.test.ts` fails (module missing).
- [ ] **Step 3:** Implement the types and `src/device/info.ts`.
