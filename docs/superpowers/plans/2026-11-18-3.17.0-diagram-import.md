# 3.17.0 Diagram and Picture Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** File › Import text or CSV… also reads diagram files — Visio `.vsdx`, SVG, PDF and pictures (PNG/JPG, text read on the device) — one file or a whole folder, through the same preview, matching and re-import rules as 3.15.0.

**Architecture:** Each reader turns a file into a `DiagramModel` (shapes with labels/data/boxes, and connectors between them), except PDF, whose text goes through the existing `readImport` auto mode. `diagramToSpec` (ported from RackMap) turns models into the existing `ImportSpec`, so `planImport` / `applyImport` / the preview are reused. The PDF reader (pdf.js) and picture reader (tesseract.js) are loaded only when used: the web build serves them from `/readers/` (copied from `node_modules` at `build:web`), the desktop app and dev mode load the same pinned versions from jsDelivr, so `Rackwright.exe` does not grow. Front end only: no Rust or server change.

**Tech Stack:** React + TS in `rackwright-tauri/src`; jszip + fast-xml-parser (already dependencies) for `.vsdx`; `pdfjs-dist@4.10.38`; `tesseract.js@7.0.0` with `tesseract.js-core@6.1.2` and `@tesseract.js-data/eng@1.0.0` (`4.0.0_best_int/eng.traineddata.gz`).

**Spec:** `docs/superpowers/specs/2026-11-17-rackmap-merge-design.md` § Imports (line 66) and call 5 (line 101). RackMap source (copying allowed): `parseVsdx`/`vsdxPage`, `parseSvg`/`svgModel`/`sanitizeSvg`, `parsePdf`, `diagramToSpec`, `parseTsv`, `wordsToLabels`, `analyseShapes`, `eraseLineArt`, `parseImage`. The controller copies the RackMap source to `.superpowers/sdd/<plan>/rackmap-diagram.js` for implementers.

## Global Constraints

- Exact copy:
  - Format choice added to the existing list: `Diagram files (Visio, SVG, PDF, picture)`. Automatic picks it for `.vsdx`, `.svg`, `.pdf`, `.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`, `.bmp` files.
  - File chooser accepts those plus the old ones; a second control `Choose a folder…` picks a folder (`webkitdirectory`); on the web a dropped folder is read too (up to 4 levels deep).
  - Checkbox `Include end-user devices (PCs, laptops, printers, phones)`, off by default, shown only for diagram files.
  - Status while reading: `Reading NAME…`; first picture: `Loading the picture reader (first time only, about 10 MB)…`; first PDF: `Loading the PDF reader (first time only)…`.
  - Warnings: `NAME: no shapes found.`, `NAME: no readable text was found.`, `NAME: old Visio file — open it in Visio and save it as .vsdx first.`, `NAME: this kind of file can't be read — skipped.`, `NAME: the picture reader couldn't load. Check the internet connection and try again.` (desktop) / `NAME: the picture reader couldn't load. Try again.` (web), same two for `the PDF reader`, `Left out N end-user device(s) (PCs, printers, phones…). Tick “Include end-user devices” to bring them in.`, `Ignored N shape(s) that look like labels, titles, clouds or decoration.`
  - Errors: `None of these files can be read — add a .vsdx, .svg, .pdf or picture file.`, `No equipment was found in these files.`
  - Folder list rows: kind (`Visio`, `Visio (old)`, `SVG`, `PDF`, `Picture`, `Text`, `—`), relative path, size (`12 KB` / `1.4 MB`).
- Diagram devices not inside a drawn rack: a new device goes **off-rack**; a matched device is **not moved**. Devices inside a rack shape get that rack, U and height from geometry.
- Pinned reader URLs (desktop and dev): `https://cdn.jsdelivr.net/npm/pdfjs-dist@4.10.38/build/pdf.min.mjs` and `…/build/pdf.worker.min.mjs`; `https://cdn.jsdelivr.net/npm/tesseract.js@7.0.0/dist/tesseract.min.js`, worker `…/tesseract.js@7.0.0/dist/worker.min.js`, core `https://cdn.jsdelivr.net/npm/tesseract.js-core@6.1.2/`, lang `https://cdn.jsdelivr.net/npm/@tesseract.js-data/eng@1.0.0/4.0.0_best_int/`. Web build: the same files under `/readers/pdfjs/`, `/readers/tesseract/`, `/readers/tesseract-core/`, `/readers/eng/` (only the `*lstm.wasm.js` core files and `eng.traineddata.gz`).
- Files never leave the machine; only the reader code is downloaded. SVG is sanitised (scripts, foreignObject, iframes, `on*` attributes, javascript:/http(s): hrefs removed) before it touches the page.
- Colours via `v(token)`; literal hex `// theme-ok`. Plain-language copy. Test fixtures use made-up names (`EX-SW01`, `Example IT`). Desktop build must keep working; web-only behaviour behind `IS_WEB`.
- Old text/CSV behaviour unchanged (all `scripts/imports.test.ts` keep passing).

## Review Focus

1. Re-importing the same diagram: second preview shows every row `same` and no cables to add (pin in Task 1 tests through `planImport`/`applyImport`).
2. A diagram after an Auvik import: devices matched by name keep their rack position; unmatched ones go off-rack, never into the target rack's free U (Task 1 test).
3. A hostile SVG (script tag, `onload`, `javascript:` link) imports without running anything (Task 3 sanitiser test, pure string/DOM-free where possible).
4. Reader download fails (offline desktop, or the `/readers/` URL falls back to `index.html` on the web): a clear warning per file, the other files still import, and the next try retries the download (Task 4 tests on the loader with a fake fetch/loader).
5. A folder with mixed junk (`.docx`, `.vsd`, `Thumbs.db`) still imports the readable files, listing the rest as skipped (Task 5).

### Task 2: Visio .vsdx reader

**Files:** Create `rackwright-tauri/src/imports/vsdx.ts`; test `rackwright-tauri/scripts/vsdx-import.test.ts`.

**Interfaces — produces:** `export async function parseVsdx(data: ArrayBuffer | Uint8Array, fileName: string): Promise<DiagramModel[]>` — one model per page, `source` = `FILE · PAGE`, `yUp: true`. Port of RackMap `parseVsdx`/`vsdxPage` using **jszip** (unzip) and **fast-xml-parser** (no DOMParser, so it runs in Node tests): masters from `visio/masters/masters.xml` (`NameU`), page names from `visio/pages/pages.xml`, shapes walked recursively with group offsets (`PinX - LocPinX`), text, `Property` section rows (`Label` → `Value`), 1-D shapes (`BeginX/EndX`) as connectors resolved through `Connect` elements, else the nearest shape within 0.25 in; child text/data rolled up into the top-level group. Throws `Error("no drawing pages found")` when there are none; a non-zip throws `Error("not a .vsdx file")`.
