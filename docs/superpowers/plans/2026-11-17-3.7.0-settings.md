# 3.7.0 Settings — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Settings screen with a Profile (everyone) and, for admins on the web, Company branding, New rack defaults, Users and Server update; the server stores system settings, per-user preferences and the company logo.

**Architecture:** Server: one `settings` row holding the system settings JSON, an `assets` table for uploaded files (only `logo` in this release; the report assets in 3.9/3.10 reuse it), and a `prefs` JSON column on `users`. Front end: `src/settings/` holds a `SettingsStore` with a web implementation (HTTP) and a desktop one (localStorage), a `useSettings()` context consumed by App, and the `SettingsScreen` UI. Theme accent and units are applied from it.

**Tech Stack:** Rust axum + rusqlite (server, tests in `web/server/tests/api.rs`), React 18 + TS (front end, tests `npx tsx scripts/*.test.ts`).

**Spec:** `docs/superpowers/specs/2026-11-16-look-and-feel-design.md` (sections "Settings", "Calls made after the builder review").

## Global Constraints

- `web/API.md` is changed first (Task 1) and is the contract both sides follow.
- No Rust toolchain on this PC: Rust is first compiled by CI. Keep Rust changes plain and close to the existing handlers' style (`auth`, `auth_admin`, `parse`, `json_ok`, `ApiError`). Never end a block with `stmt.query_map(...)?.collect()?` — bind to a variable first (E0597).
- Web-only UI behind `IS_WEB`; no static `@tauri-apps` imports; desktop keeps working without a server.
- Colours via `v("token")`; "no stray hex" stays green. No new npm or cargo dependencies.
- No company names or real data in code, tests or fixtures (use "Example IT").
- Copy: plain, short sentences.

## Rulings for this release (scope)

- Report branding (report colours, font, artwork, address line, Word template) ships with the report releases (3.9 / 3.10), reusing the asset mechanism built here. 3.7 branding = company name, app logo, accent colour.
- Theme choice ships in 3.8 with the light theme (only dark exists now).
- New rack defaults = default rack model and default height (the only choices the New/Add rack dialog has). Auvik "Include as" defaults are not added.
- Desktop stores preferences and branding (logo as a data URL, max 1 MB) in localStorage.

## Review Focus

1. A non-admin calling `PUT /api/settings`, `PUT/DELETE /api/assets/logo` gets 403; signed-out callers get 401, except `GET /api/branding` and `GET /api/branding/logo`, which work signed out (the sign-in page uses them).
2. Upload validation: unknown asset name → 404; wrong Content-Type (only `image/png`, `image/svg+xml`, `image/jpeg`, `image/webp` for `logo`) → 400; over 2 MB → 400. SVG is served with `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'` and `X-Content-Type-Options: nosniff` so an uploaded SVG cannot run script.
3. Changing email: wrong current password → 400, email taken (case-insensitive) → 409, and the session keeps working afterwards.
4. Preferences survive unknown keys (a 3.8 client saving `theme` to a 3.7 server and back loses nothing): `PUT /api/me/prefs` stores the whole JSON object as given (≤ 16 KB, must be an object).
5. An accent colour that isn't `#rrggbb` is refused (400) by the server and by the form; the Rackwright logo mark keeps its own blue (`brand` token) whatever the accent.

### Task 1: API contract and server

**Files:** Modify `web/API.md`, `web/server/src/lib.rs` (routes, users migration, `/api/me` PATCH, prefs), create `web/server/src/settings.rs` (settings + assets + branding handlers), test `web/server/tests/api.rs`.

**API (write into API.md, new section "Settings and branding", and extend "Setup and sign-in"):**

| Method & path | Who | Body | Result |
|---|---|---|---|
| `PATCH /api/me` | signed in | any of `{name, email, current_password}`; `email` requires `current_password` | `User`; 400 wrong password / bad email, 409 email taken |
| `GET /api/me/prefs` | signed in | — | the stored JSON object, `{}` if none |
| `PUT /api/me/prefs` | signed in | a JSON object (≤ 16 KB) | the stored object |
| `GET /api/settings` | signed in | — | `{ "settings": {...}, "assets": [{name, mime, size, updated_at}] }`; settings default `{}` |
| `PUT /api/settings` | admin | a JSON object (≤ 64 KB). Known keys validated: `company_name` string ≤ 100, `accent` `#rrggbb`, `rack_default_model` string, `rack_default_u` integer 1–60. Unknown keys kept. | the stored object |
| `PUT /api/assets/:name` | admin | raw file bytes; `Content-Type` header is the mime | `{name, mime, size, updated_at}`. Names allowed now: `logo` (png, svg+xml, jpeg, webp; ≤ 2 MB). Unknown name 404, bad type or size 400 |
| `DELETE /api/assets/:name` | admin | — | `{}` (also when absent) |
| `GET /api/assets/:name` | signed in | — | the bytes with their `Content-Type`; 404 if absent |
| `GET /api/branding` | anyone | — | `{ "company_name": string, "accent": string or null, "has_logo": bool }` |
| `GET /api/branding/logo` | anyone | — | logo bytes (same headers as above) or 404 |

Schema (create if missing; in `settings.rs` `pub fn migrate(conn)` called from `build_app` after `clients::migrate`):
- `CREATE TABLE IF NOT EXISTS settings (id INTEGER PRIMARY KEY CHECK (id = 1), value TEXT NOT NULL)`
- `CREATE TABLE IF NOT EXISTS assets (name TEXT PRIMARY KEY, mime TEXT NOT NULL, data BLOB NOT NULL, updated_at TEXT NOT NULL)`
- `users.prefs TEXT NOT NULL DEFAULT '{}'` added with `ALTER TABLE` when `PRAGMA table_info(users)` lacks it (same pattern as `clients::migrate` adding `racks.site_id`).

Served SVG/any asset headers: `Content-Type: <mime>`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'`, `Cache-Control: no-cache`.

### Task 2: Front-end settings store and context

**Files:** Create `src/settings/types.ts`, `src/settings/store.ts`, `src/settings/context.tsx`, `src/units.ts`; modify `src/api.ts` (new calls), `src/theme.ts` (accent override + `brand` token for the logo), `src/Logo.tsx` (use `brand`), `src/racks.ts` (`dimsText` gains a units argument); Test: `scripts/settings.test.ts`.

**Interfaces (produces):**
- `types.ts`: `export type Units = "mm" | "in"`; `export type StartScreen = "new" | "last" | "clients" | "racks"`; `export interface Prefs { units?: Units; start?: StartScreen; last_rack?: { id?: number; path?: string; name?: string }; [k: string]: unknown }`; `export interface SystemSettings { company_name?: string; accent?: string; rack_default_model?: string; rack_default_u?: number; [k: string]: unknown }`; `export interface Branding { company_name: string; accent: string | null; logo_url: string | null }`.
- `store.ts`: `export interface SettingsStore { getPrefs(): Promise<Prefs>; setPrefs(p: Prefs): Promise<Prefs>; getSystem(): Promise<SystemSettings>; setSystem(s: SystemSettings): Promise<SystemSettings>; getBranding(): Promise<Branding>; setLogo(file: File | null): Promise<void> }` and `export function settingsStore(): SettingsStore` — web uses the endpoints above (`logo_url` = `/api/branding/logo?v=<updated_at>` when present); desktop uses localStorage keys `rw.prefs`, `rw.system` and `rw.logo` (data URL; reject files over 1 MB with the message "Pick an image under 1 MB.").
- `context.tsx`: `export function SettingsProvider({ children }: { children: ReactNode })`, `export function useSettings(): { prefs: Prefs; system: SystemSettings; branding: Branding; savePrefs(p: Partial<Prefs>): Promise<void>; saveSystem(s: Partial<SystemSettings>): Promise<void>; setLogo(f: File | null): Promise<void>; reload(): Promise<void> }` — on load and after every save, calls `applyAccent(system.accent ?? null)`.
- `units.ts`: `export function fmtLen(mm: number, u: Units): string` → mm: `"600 mm"`; in: one decimal, `"23.6 in"`. `export function fmtDims(w: number | undefined, d: number | undefined, u: Units): string` with the same wording as today's `dimsText` (`"600 x 1070 mm"`, `"600 mm wide"`, `"size varies"`; inches `"23.6 x 42.1 in"`).
- `theme.ts`: add token `brand: "#2a6fdb"`; `export function isHex6(s: string): boolean`; `export function applyAccent(hex: string | null, el?: HTMLElement): void` — sets `--rw-accent` to `hex` (or back to `DARK.accent` when null) and `--rw-accent-soft` to the accent mixed 25 % over `DARK.panel` (`mixHex(a, b, t)`, exported).
