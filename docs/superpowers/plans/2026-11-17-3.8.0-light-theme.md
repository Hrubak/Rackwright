# 3.8.0 Light theme Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dark, Light and Match my computer themes for the whole app including the drawings; exports always draw with the light set.

**Architecture:** `LIGHT` (same keys as `DARK`, written by the controller in `src/theme.ts`) is applied as CSS variables by `applyTheme`. The theme is a per-user preference (`Prefs.theme`). "Match my computer" follows `prefers-color-scheme` live. PDF export resolves variables with `LIGHT`.

**Tech Stack:** React 18 + TS, CSS custom properties.

**Spec:** `docs/superpowers/specs/2026-11-16-look-and-feel-design.md` (Themes; "Light drawings for exports").

## Global Constraints

- Default theme: dark. Choices and copy: "Dark", "Light", "Match my computer". Values `"dark" | "light" | "system"`.
- Plate.tsx faceplates, device colours and user-chosen cable colours do not change with the theme.
- Exports (PDF) always use the light set. Visio export unchanged.
- Colours only through tokens; "no stray hex" stays green.
- No server change: prefs are a free JSON object already.

## Review Focus

- Switching theme while the app is open repaints everything at once (no reload), including the accent's soft tint.
- "Match my computer" follows an OS change while the app is open.
- A company accent stays applied after a theme switch.
- The rack drawing's validity overlay (green/amber/red while dragging) uses the current theme's colours.
- The first paint before settings load uses the theme saved on this computer (no dark flash for light users).

### Task 1: Theme switching, preference and exports

**Files:** `src/theme.ts`, `src/settings/types.ts`, `src/settings/context.tsx`, `src/settings/SettingsScreen.tsx`, `src/main.tsx`, `src/RackView.tsx`, `src/export/pdf.ts`, `scripts/theme.test.ts`.

- `ThemeName = "dark" | "light"`, `ThemePref = ThemeName | "system"`. `palette(name): Record<Token,string>`; `currentTheme(): ThemeName` (reads `data-theme` on the root, default dark); `resolveTheme(pref, prefersDark: boolean): ThemeName`.
- `applyTheme(name)` sets `data-theme` and every `--rw-*` from that palette, then re-applies the stored accent (keep the last accent passed to `applyAccent` in a module variable). `applyAccent` mixes `accent-soft` against the current palette's `panel` (light: 0.18 share of accent, dark: 0.25).
- `Prefs.theme?: ThemePref`. Profile › Preferences gets "Theme" (Dark / Light / Match my computer) above Units. Saving applies at once.
- SettingsProvider: whenever prefs.theme changes (and on load), apply `resolveTheme`. For "system", listen to `matchMedia("(prefers-color-scheme: dark)")` change events and re-apply; remove the listener when the pref changes. Also cache the chosen pref in localStorage `rw.theme` on every apply; `main.tsx` applies `resolveTheme(localStorage rw.theme ?? "dark", matchMedia…)` before first render instead of `applyTheme("dark")`.
- RackView validity colours: use `palette(currentTheme())[…]` instead of `DARK[…]` (they need a literal hex for the alpha suffix).
- pdf.ts: `resolveSvgVars(svg, LIGHT)`. Anything else in pdf.ts that reads DARK switches to LIGHT. The PDF page background is white.
- Tests in scripts/theme.test.ts: `LIGHT` has exactly DARK's keys; all LIGHT values are hex; `resolveTheme("system", true) === "dark"`, `resolveTheme("system", false) === "light"`, `resolveTheme("light", true) === "light"`; `resolveVars("var(--rw-bg)", LIGHT) === "#f4f5f7"`.
